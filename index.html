About关于我

我相信好的技术应该安静地解决问题，而不是把复杂度留给使用者。

我习惯从“为什么做”开始，而不是从框架开始。拿到一个需求，先把它拆成用户路径、数据流和失败场景， 再决定用什么技术。做 PsyCare 时，隐私不是最后补上的功能，而是从数据库字段、接口序列化到统计聚合一路贯穿的约束。

我也喜欢把学习过程写下来：一个检索效果不好，是切片的问题、召回的问题，还是提示词的问题？ 把变量控制住，一次次复现，直到能解释结果。对我来说，能讲清楚和能跑起来同样重要。

目前主要在 Python / Java 后端与 AI 应用方向持续实践，也愿意接触真实业务里的脏活累活。

  1. 01

    先跑通，再打磨

    先让最小闭环成立，再谈架构和体验。能演示、能验证，比纸面上的完美更重要。

  2. 02

    隐私不是附加项

    敏感数据在写入前加密、返回前掩码、统计前聚合。保护应该发生在链路上，而不是口号里。

  3. 03

    让结果有出处

    无论是检索回答还是项目决策，都尽量留下可追溯的依据，而不是只给一个看起来正确的结论。
